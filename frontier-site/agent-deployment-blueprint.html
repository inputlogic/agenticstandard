    Forty-five minutes to a blueprint for your first agent.

    Microsoft publishes a reference architecture and deployable templates for running agents on Azure. We take you through it from the beginning: a short explanation of each part, then the decisions it needs, with the reasons to pick one option over another. When we finish, this page has drawn your environment and written the settings we deploy it from with Terraform.

      Words we will use
      Landing zone
      A prepared area of Azure with its network, identities and rules already in place, ready for one workload to move in.
      Foundry
      Microsoft's service for models and agents. The agent, its models and its knowledge live in a Foundry project.
      Hub and spoke
      One shared network (the hub) with firewall and DNS, and a separate network (a spoke) for each workload.
      Private endpoint
      A private address for an Azure service inside your network, so it is not reachable from the internet.
      Terraform
      A tool that builds cloud resources from text files, and keeps a record (state) of what it built.
      azd
      Microsoft's command-line tool that runs the template: it provisions the foundation, then deploys the agent.
      Managed identity
      An identity Azure gives a service so it can call other services without a stored password or key.
      Token
      The unit models count in, roughly three-quarters of a word. Capacity is measured in tokens per minute.
